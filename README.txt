PORTABLECREATER — сборка портативных версий проектов из PyCharm
================================================================

Что это
--------
Инструмент из двух файлов:

  Build_Portable.bat   — запускается двойным кликом (или папка проекта просто
                         перетаскивается на него мышкой)
  make_portable.py     — сам движок сборки (его трогать не нужно)

Он берёт обычный проект из PyCharm (с его venv) и делает из него папку,
которую можно перенести на любой другой компьютер и запустить там: без
интернета, без установленного Python, без пересборки.

Уже собрано и проверено:  X:\PortableCreater\Builds\CropImage_Portable
(портативная сборка вашего примера CropImage, внутри всё то же, что будет
получаться для других проектов)


Как пользоваться (два шага)
---------------------------
Шаг 1. Собрать.
   Either перетащите папку проекта на Build_Portable.bat,
   Or запустите Build_Portable.bat и впишите путь к папке проекта.

   Результат появится рядом с проектом:  <ИмяПроекта>_Portable
   Например: X:\...\CropImage  ->  X:\...\CropImage_Portable

Шаг 2. Перенести и запустить.
   Скопируйте ВСЮ папку <ИмяПроекта>_Portable целиком в любое место:
   флешка, другой диск, другой компьютер, папка с русским именем и
   пробелами — можно как угодно. Внутри можно всё переименовывать.
   Затем двойной клик по Start.bat внутри этой папки — программа запускается.

   Start.bat        — запуск с окном консоли (видно вывод и ошибки)
   Start_gui.bat    — тот же запуск без окна консоли (для программ с окном)
   Start.bat  имя.py — запустить другой стартовый файл
                      (например: Start.bat  Crop4.py  или  Start.bat  src\main.py)
   Run_имя.bat      — отдельные запускатели, если точек входа в проекте
                      оказалось несколько

Ничего дополнительно делать не нужно: ни pip, ни activate, ни установка Python.


Что скрипт читает и определяет сам
----------------------------------
  • папку окружения проекта (venv, .venv, env или любую другую — ищет по
    файлу pyvenv.cfg);
  • версию Python проекта (3.7, 3.10, 3.12 ...) из pyvenv.cfg, а если его нет —
    по кэшу __pycache__ (Crop4.cpython-310.pyc -> 3.10);
  • разрядность (32 или 64 бита) по файлу venv\Scripts\python.exe;
  • все зависимости: разбирает import-ы во всех .py файлах проекта и соотносит
    их с пакетами из venv, версии пакетов берёт из метаданных (Pillow 9.5.0,
    tkinterdnd2 0.4.3 ...); requirements.txt, если есть, сверяется с venv;
  • стартовый файл: ищет файлы с `if __name__ == "__main__":` и выбирает
    наиболее подходящий (main.py, файл с именем проекта и т.п.).

После этого он:
  • копирует исходники проекта (venv, .idea, кэши — не копируются);
  • копирует целый Python той же версии и разрядности в папку runtime\
    (python.exe, pythonXX.dll, DLLs, стандартная библиотека, tcl/tk);
  • укладывает пакеты из venv в runtime\Lib\site-packages;
  • пишет Start.bat (и Start_gui.bat) и файл PORTABLE_INFO.txt с инструкцией
    и полным списком версий;
  • САМ ПРОВЕРЯЕТ результат: запускает собранную сборку из другой папки, а
    затем копирует всю сборку во временную папку (эмуляция переноса на другой
    компьютер) и запускает оттуда, проверяя, что сборка нигде не ссылается на
    исходные папки проекта и на исходный Python. Если что-то не автономно —
    об этом будет написано в конце сборки и в PORTABLE_INFO.txt.

Ваш исходный проект при этом не меняется и не удаляется.


Что будет внутри собранной папки
--------------------------------
  Start.bat              — запуск программы
  Start_gui.bat          — запуск без окна консоли (если в проекте есть GUI)
  Run_*.bat              — запуск других стартовых файлов (если их несколько)
  PORTABLE_INFO.txt      — инструкция + список пакетов и версий + результаты проверки
  runtime\               — переносимый Python (он же с пакетами)
  runtime\Lib\site-packages — все пакеты проекта
  *.py и остальные файлы — копия вашего проекта


Что нужно на компьютере, ГДЕ СОБИРАЕТЕ
--------------------------------------
  • Любой Python 3.6+ — чтобы запустить сам Build_Portable.bat (обычно уже есть).
  • Тот же Python, что у проекта (та же версия и та же разрядность), — из него
    берётся переносимый рантайм. PyCharm-овские venv стандартной библиотекой
    не пользуются, поэтому нужен полный установщик Python. Если такого Python
    на сборочном ПК нет, скрипт так и напишет и предложит:
      --runtime C:\Python310      (путь к папке установки Python)
    либо установите Python нужной версии с python.org и повторите сборку.
    Интернет при этом не нужен — только наличие установщика/интерпретатора.

Требования на компьютере, ГДЕ ЗАПУСКАЕТЕ
----------------------------------------
  • Windows той же разрядности, что и Python в проекте (сборка 64-битная
    работает на 64-битной Windows; для 32-битного Python — 32-битная сборка).
  • Windows 10/11 — всё нужно уже есть. Windows 7/8 для Python 3.9+ может
    попросить обновление системы (KB2999226 / UCRT) — но на Python 3.7-3.8,
    как в вашем примере, такого требования нет.
  • Папку runtime\ нельзя удалять и нельзя переносить отдельно от Start.bat.


Полезные ключи (запуск из командной строки)
-------------------------------------------
  Build_Portable.bat  C:\proj                        — обычная сборка
  Build_Portable.bat  C:\proj  --out  D:\builds      — собрать в другое место
  Build_Portable.bat  C:\proj  --overwrite           — пересобрать поверх старой
  Build_Portable.bat  C:\proj  --python 3.10         — задать версию Python вручную
  Build_Portable.bat  C:\proj  --entry  main.py      — задать стартовый файл
  Build_Portable.bat  C:\proj  --venv  myenv         — указать папку окружения
  Build_Portable.bat  C:\proj  --runtime C:\Python310— указать, откуда брать Python
  Build_Portable.bat  C:\proj  --lean                — не копировать пакеты venv,
        которые нигде не импортируются (в вашем примере экономит ~13 МБ: не
        едут PyInstaller, pip, setuptools). Надёжнее без этого ключа.
  Build_Portable.bat  C:\proj  --no-test             — не проверять сборку
  Build_Portable.bat  C:\proj  --no-relocate         — не делать проверку переноса
        (проверка переноса копирует сборку ещё раз, поэтому занимает время)


Если что-то не работает
-----------------------
  • "На этом компьютере нет того Python..." — установите ту же версию Python,
    что у проекта (или укажите её через --runtime). Портировать можно только
    с тем же интерпретатором, на котором проект работал.
  • На другом ПК программа не запускается: чаще всего не та разрядность
    Windows или была скопирована не вся папка (например без runtime\).
  • Сообщает, что модуля нет — значит его не было в venv проекта: установите
    его в venv (pip install ...) и соберите заново; скрипт заранее предупреждает
    об этом строкой "импортируется, но не найдено в окружении проекта".
  • Программа ищет свои файлы не там: Start.bat делает текущей папкой папку
    сборки. Если программе нужна конкретная папка с данными — положите её рядом
    с Start.bat (всё, что было в проекте, лежит рядом).
  • Старый start.bat из проекта: если в проекте уже был свой start.bat, он
    сохранён как start.bat.orig.txt (он обращается к venv и здесь работать не
    будет). Для запуска используйте новый Start.bat.


Ваш пример (CropImage)
----------------------
Проект X:\PortableCreater\SourseExampleProject\CropImage: Python 3.7.0 64-бит,
Pillow 9.5.0, tkinterdnd2 0.4.3, стартовый файл Crop4.py. Уже собрано:
  X:\PortableCreater\Builds\CropImage_Portable   (~58 МБ)
Запуск на этом или любом другом 64-битном ПК: двойной клик по Start.bat
(или Start_gui.bat — без окна консоли). Проверено: PIL, tkinter 8.6 и
tkinterdnd2 загружаются, запуск из перенесённой и переименованной папки работает.

Примечание: свой venv вы запустить не могли, потому что он был создан на
Python из C:\Python37 и в pyvenv.cfg записаны пути к тому месту. Этот инструмент
именно поэтому копирует сам интерпретатор внутрь runtime\ и не оставляет никаких
привязок к исходным папкам.
